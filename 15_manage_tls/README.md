# 🔐 Managing TLS Certificates in Kubernetes

This guide explains how to generate and approve TLS certificates for users in a Kubernetes cluster using the **CertificateSigningRequest (CSR)** process.

---

## 📌 1. Understanding Certificates and Keys

### 🔑 Private Key

Private keys are confidential and must never be shared.

Common naming conventions:

- `server.key`
- `server-key.pem`
- `client.key`
- `client-key.pem`

> 🔎 Files containing **"key"** in their name are private keys.

---

### 📜 Certificate

Certificates are public and can be shared.

Common naming conventions:

- `server.crt`
- `server.pem`
- `client.crt`
- `client.pem`

> 🔎 Certificates usually end with `.crt` or `.pem`.

---

# 👤 Example Scenario: Adding a New Admin User

A new user named **adam** joins the team as an admin.
You need to provide him access to the Kubernetes cluster using TLS certificates.

---

# 🛠 Step-by-Step Process

---

## ✅ Step 1: Generate Private Key

```bash
openssl genrsa -out adam.key 2048
```

This creates:

```
adam.key
```

---

## ✅ Step 2: Create Certificate Signing Request (CSR)

```bash
openssl req -new -key adam.key -out adam.csr -subj "/CN=adam"
```

This creates:

```
adam.csr
```

`/CN=adam` → Common Name (username in Kubernetes)

---

### ❗ If You Get OpenSSL Config Error (Windows)

If you see:

```
No such file or directory
```

Set the OpenSSL config path manually:

```powershell
set OPENSSL_CONF=C:\Program Files\Git\usr\ssl\openssl.cnf
```

---

# 📦 Step 3: Convert CSR to Base64

Kubernetes requires the CSR in Base64 format.

### 🐧 Linux

```bash
cat adam.csr | base64 | tr -d "\n"
```

---

### 🪟 Windows PowerShell

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes(".\adam.csr"))
```

Copy the Base64 output — you will use it in `csr.yaml`.

---

# 📄 Step 4: Create csr.yaml

Example:

```yaml
apiVersion: certificates.k8s.io/v1
kind: CertificateSigningRequest
metadata:
  name: adam
spec:
  request: <PASTE_BASE64_CSR_HERE>
  signerName: kubernetes.io/kube-apiserver-client
  usages:
    - client auth
```

---

# 🚀 Step 5: Apply CSR to Cluster

```bash
kubectl apply -f csr.yaml
```

Check status:

```bash
kubectl get csr
```

You’ll see:

```
NAME   AGE   SIGNERNAME                              REQUESTOR   CONDITION
adam   10s   kubernetes.io/kube-apiserver-client     ...         Pending
```

---

# ✅ Step 6: Approve the CSR

```bash
kubectl certificate approve adam
```

Check again:

```bash
kubectl get csr
```

Now it should show:

```
Approved,Issued
```

---

# 📥 Step 7: Retrieve the Issued Certificate

```bash
kubectl get csr adam -o yaml > issuecert.yaml
```

Inside the YAML, you will find:

```yaml
status:
  certificate: LS0tLS1CRUdJTiBDRVJUSUZJQ0FURS0t...
```

This certificate is Base64 encoded.

---

# 🔓 Step 8: Decode the Certificate

### 🐧 Linux

```bash
echo "BASE64_CERTIFICATE_HERE" | base64 -d
```

---

### 🪟 Windows PowerShell

```powershell
[System.Text.Encoding]::UTF8.GetString([System.Convert]::FromBase64String("BASE64_CERTIFICATE_HERE"))
```

Save the decoded output as:

```
adam.crt
```

---

# 📤 Step 9: Share with User

Now share with Adam:

- `adam.key` (private key – generated by user)
- `adam.crt` (approved certificate)
- Cluster CA certificate (if required)

He can now configure `kubeconfig` to access the cluster.

---

# 🧠 Summary Flow

```
Generate Key → Create CSR → Convert to Base64 → Create CSR YAML → Apply → Approve → Retrieve Certificate → Decode → Share
```
